Local Asset Search by tag

Windows 本地**文件夹**素材库工具。目标为 Windows 10 1809+ / Windows 11，使用 .NET 8 WPF、SQLite，并尽可能复用 Windows 自带组件。

工具管理的是**文件夹**：给文件夹打标签、按标签和关键字筛文件夹、用文件夹里命名最靠前的图片当封面。**图片本身不进索引、不出现在结果里**，磁盘上的文件也永远不会被移动或修改。

## 功能

**索引与浏览**
- 扫描目录及子目录，只索引**文件夹**（图片和 PDF 都不入库）。
- 文件夹封面读取直接子文件：优先主文件名恰为 `0` 的图片（`0.jpg` / `0.png`），否则按资源管理器的**自然顺序**取第一张（`1.png < 2.png < 10.png`）。只取图片，不递归子目录。
- **分页浏览**：每页 30 / 60 / 120 / 240 条，支持首页 / 上一页 / 下一页 / 末页和跳转；翻页或改变筛选后会自动回到顶部。
- **卡片**（自上而下）：封面区固定 266×372，图片**等比居中、尽可能放大、绝不裁剪**（`Uniform`，比框小的图也会放大；宽图上下留白、很高的图会缩到框内），勾选框在封面左上角 → **文件夹里的图片数量**（如 `27 张图片`，没有图时显示「无图片」） → 标签芯片 → **作品名称**（贴底，外观是文本框，点击打开文件夹）。
- **点封面在工具内看图**：内置看图窗口，**← → / PageUp·PageDown / 空格翻页**，Home·End 首末，**Ctrl+W / Esc 关闭**，底部显示「当前 / 总数」和文件名。图片列表和封面取图共用同一套顺序，所以打开就停在封面那张。
- **鼠标点窗口任意处翻页**；到**最后一页**时点任意处即关闭。
- **GIF 动图**：看图窗口遇到 `.gif` 会按每帧延迟循环播放；卡片封面取 GIF 首帧，GIF 也计入「图片数量」和看图列表。
- **定时自动翻页**：底部下拉框选间隔（不自动 / 2 / 3 / 5 / 10 秒），或按 **A** 键快速开关。自动翻到最后一页后等满一个间隔**自动关闭**。
- **看图窗口可以多开**：每点一次封面开一个新窗口，各看各的。窗口**不挂在主窗口下**，所以能各自出现在 Alt+Tab 和任务栏里，随时切回工具窗口。
- **点作品名称**在资源管理器里打开这个文件夹。
- **卡片右键菜单**：看图（左右键翻页） / 用 Windows 图片打开第一张 / 打开文件夹路径 / 给文件夹打标签… / 从工具中删除。
- **重扫自动清理**：再次扫描同一个目录时，磁盘上已经不存在、之前索引过的文件夹会被**真正删除**（标签关联一起清），状态栏会报告清理了几条。
  删除前会再确认一次路径确实不在磁盘上——外接盘临时没挂上不会误删。

**排序**（顶部下拉切换，选择会记住）
- **结尾 {页数,位置}**（默认）：按目录名末尾的 `{收藏夹页码,页内序号}` **升序**——页码小的在前，同一页里序号小的在前。
  命名规则来自 AHRI8Backup：`标题{作者}{收藏夹页码,页内序号}`，例如 `a{b}{1,3}` 表示第 1 页第 3 个；多作者时是多个 `{作者}` 段，只认末尾那一组。
- **结尾 {页数,位置} 倒序**：同上但反过来——页码大的在前，同一页里序号大的在前。例如 `xxx{a}{2}` 排在 `xxx{a}{1}` 前面。
- 两种按数字排的模式下，解析不出这组数字的（例如根目录自己）都排在最后，它们之间按名称排序。
- 末尾只写一个数字也认：`xxx{a}{2}` 按页码 2、位置 0 处理。
- **首字母 A→Z / Z→A**：按**标题**排序，标题取第一个 `{` 之前的内容，不会把后面的 `{作者}{页码,序号}` 算进去。不分大小写。

**标签**
- **标签分类**：每个标签可归入一个分类（分类就是个文本字段，不需要先建分类）。筛选栏、打标签窗口、文件夹标签窗口都按分类分组，未分类的排最后。
- **标签管理**：改名、改分类、删除，并显示每个标签的使用次数。删除标签只解除关联，不动磁盘目录。
- **给文件夹打标签**：多选文件夹，标签框三态显示（全选／半选／未选），一次批量添加或移除；每个文件夹行下方直接列出它已有的标签。
- **打标签时直接选已有标签**：按分类列出全部标签，勾选即生效，也能顺手新建（可同时填分类）。
- 多标签 AND / OR 搜索；点卡片上的标签芯片即可按该标签筛选。父文件夹的标签会匹配它下面的子文件夹。

**其它**
- **导出清单**：把当前筛选出的文件夹导成文本清单——序号 / 文件夹名称 / 标签 / 完整路径，制表符分隔（可直接拖进 Excel 分列）。表头会写明导出时间、排序方式、关键字和标签筛选条件。
- **从工具中删除（不删磁盘目录）**：勾选卡片后批量移除，只删索引和标签关联。路径会记进隐藏列表，**重新扫描也不会再收进来**；移除文件夹会连同它下面的子目录一起移除。误删可用「恢复已隐藏」清空隐藏列表（需重扫恢复索引）。
- **浅色 / 深色主题**：右上角按钮切换，选择会记住。
- **应用图标**：`Assets\app.ico`（附件里的文件夹 + 小狗照片 + `IMG_01` 标签，透明背景、多尺寸），
  资源管理器、任务栏、快捷方式和窗口标题栏都用这一张。
- **库另存为 / 读取库**：把标签、文件夹列表、标签关联、根目录和隐藏路径另存为 JSON（`.laslib.json`），
  换机器或重装后读取回来即可恢复，不用重新扫描/打标签；读取是合并，不会清空当前库。文档不包含图片。
- **索引和标签不放在 exe 目录**：始终保存在用户数据目录；删除、替换或重新下载 exe 都不影响。

## 依赖与下载量说明

**需要 NuGet 依赖，无法做到完全零下载**，因为 .NET/WPF 本身不提供 SQLite 数据库驱动。

本项目不使用 PDFium、PDFtoImage 或独立 SQLite 原生二进制包，只用：

- `Microsoft.Data.Sqlite.Core` 8.0.11
- `SQLitePCLRaw.provider.winsqlite3` 2.1.6
- 上述包的传递依赖 `SQLitePCLRaw.core`（NuGet 自动解析）

SQLite 通过 Windows 自带的 `winsqlite3.dll` 运行。首次还原仍需从 NuGet 下载这些托管包；还原成功后通常会缓存在本机。

## 构建

需要 Visual Studio 2022 的“.NET 桌面开发”工作负载，或 .NET 8 SDK。

```powershell
dotnet restore
dotnet build -c Release
dotnet run
```

## 发布

发布产物在 `release\` 下：

| 产物 | 体积 | 需要 .NET 8 桌面运行时 | 说明 |
|---|---|---|---|
| **单文件 · 自包含**（`1-single-file-self-contained`） | 约 162 MB | **不需要**（运行时内置） | 首次运行把原生库解包到 `%TEMP%\.net\`，TEMP 必须可写 |
| **单文件 · 框架依赖**（`2-single-file-fx-dep`） | 约 731 KB | 需要 8.0.x | 不解包、不压缩，误报率最低 |
| **普通文件夹**（`3-folder-fx-dep`） | 约 600 KB | 需要 8.0.x | 无 bundle、无自解包，最普通的 .NET 桌面程序 |

### 单文件版到底需要什么

- **单文件 · 框架依赖**：Windows 10 1809+ / Windows 11，外加 **.NET 8 桌面运行时**（`Microsoft.WindowsDesktop.App` 8.0.x）。
- **单文件 · 自包含**：Windows 10 1809+ / Windows 11，**不需要安装 .NET**；需要 `%TEMP%` 可写（首次自解包）。
- 两者都不需要：.NET Framework、VC++ Redistributable、WebView2、DirectX 额外组件。
- SQLite 用的是 **Windows 自带的 `winsqlite3.dll`**（Windows 10 1809+ 内置，本机为 3.43.2），不需要单独安装。
  没有换成自带 `e_sqlite3.dll` 的 bundle：系统组件已经足够，少一个自解包原生库也能少一点 Defender 误报面。

### 图标文件

- 源文件：`Assets\app.ico`（16–256 多尺寸）与 `Assets\app-32.png`（窗口标题栏用）。
- 源码包 `LocalAssetSearch-v0.13.0-src.zip` 内包含这两个文件。
- `release\` 根目录也保留一份，方便查看或替换；exe 已内嵌图标，**替换 exe 旁边的 ico 不会改变 exe 本身**。

> 如果 `dotnet publish` 报 `MSB4018 ... Access to the path ...\LocalAssetSearch.exe is denied`，
> 说明**上一次发布出来的 exe 正被杀软或索引占用**，MSBuild 覆盖不了它，于是**保留了旧文件而发布实际失败**。
> 这种失败不看输出很容易漏掉（产物还在，只是旧的）。处理办法：确认没有进程在跑那个 exe、稍等几秒重试，
> 或输出到新的目录名。**发布后建议核对产物版本**：
> `(Get-Item .\LocalAssetSearch.exe).VersionInfo.ProductVersion`。

### 关于被 Defender / SmartScreen 拦截

本程序没有代码签名证书，而「体积较大 + 自解包 + 压缩」的 .NET 单文件 exe 与加壳恶意软件的形态高度相似，因此被误报很常见。应对方式：

若 exe 是从压缩包或网络复制来的，右键 → 属性 → 勾选「解除锁定」。

仍然被拦就加排除项：Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项 → 添加文件/文件夹。

想要彻底避免：给 exe 做代码签名（需要付费证书）。

另注：刚构建出来的 exe 第一次启动可能报一次「拒绝访问」，等一两秒重试即可——实时防护正在扫描新文件。

## 启动失败怎么排查

程序是 `WinExe`，**没有控制台窗口**，所以启动阶段的异常不会自己显示出来。因此：

- 启动过程会写日志：优先写在 **exe 同目录** 的 `LocalAssetSearch.log`，该目录不可写时退回 `%TEMP%\LocalAssetSearch.log`。
- 启动失败会弹窗说明原因，并提供「打开日志所在文件夹」。
- 若连弹窗都没出现，说明进程在托管代码运行前就死了 —— 基本是杀软拦截或自解包失败。
- 想确认各个窗口是否都能加载，可以运行 `LocalAssetSearch.exe --selftest`：它只构造窗口、不显示，把结果写进日志后立刻退出（退出码 = 失败数）。

## 数据位置

- SQLite 数据库：`%LOCALAPPDATA%\LocalAssetSearch\assets.db`（默认；**不会**放在 exe 目录）
- 缩略图缓存：`%LOCALAPPDATA%\LocalAssetSearch\Thumbnails\`
- 主题设置：`%LOCALAPPDATA%\LocalAssetSearch\settings.ini`
- 启动日志：exe 同目录的 `LocalAssetSearch.log`（或 `%TEMP%` 下同名文件）

默认目录不可写时，按 `%APPDATA%` → `%USERPROFILE%` → `%TEMP%` 顺序回退
