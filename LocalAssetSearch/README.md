# LocalAssetSearch v0.18.0 — 少依赖版本

Windows 本地**文件夹**素材库工具。目标为 Windows 10 1809+ / Windows 11，使用 .NET 8 WPF、SQLite，并尽可能复用 Windows 自带组件。

工具管理的是**文件夹**：给文件夹打标签、按标签和关键字筛文件夹、用文件夹里命名最靠前的图片当封面。**图片本身不进索引、不出现在结果里**；平时不会移动或修改磁盘文件，只有你主动使用「删除文件夹…」时才会把文件夹移到回收站。

## 功能

**索引与浏览**
- 扫描目录及子目录，只索引**文件夹**（图片和 PDF 都不入库）。
- **识别文件索引**：扫描时优先读取每个文件夹里的 `work-id.json`，用其中的 `Title`、`Authors`、`FavoritePage/FavoritePosition`、`WorkId`、`GlobalIndex` 建立索引；没有识别文件或文件损坏时，回退到目录名末尾的 `{页数,位置}` 解析。升级旧库时会就地把已有文件夹补一遍识别信息，不必重扫。
- 文件夹封面读取直接子文件：优先主文件名恰为 `0` 的图片（`0.jpg` / `0.png`），否则按资源管理器的**自然顺序**取第一张（`1.png < 2.png < 10.png`）。只取图片，不递归子目录。
- **分页浏览**：每页 30 / 60 / 120 / 240 条，支持首页 / 上一页 / 下一页 / 末页和跳转；翻页或改变筛选后会自动回到顶部。
- **卡片**（自上而下）：封面区固定 266×372，图片**等比居中、尽可能放大、绝不裁剪**（`Uniform`，比框小的图也会放大；宽图上下留白、很高的图会缩到框内），勾选框在封面左上角 → **文件夹里的图片数量**（如 `27 张图片`，没有图时显示「无图片」） → 标签芯片 → **作品名称**（贴底，外观是文本框，点击打开文件夹）。
- **点封面在工具内看图**：内置看图窗口，**← → / PageUp·PageDown / 空格翻页**（最后一页按空格关闭），Home·End 首末，**Ctrl+W / Esc 关闭**，底部显示「当前 / 总数」和文件名。图片列表和封面取图共用同一套顺序，所以打开就停在封面那张。
- **鼠标点窗口任意处翻页**；到**最后一页**时点任意处或按**空格**即关闭。
- **GIF 动图**：看图窗口遇到 `.gif` 会按每帧延迟循环播放；卡片封面取 GIF 首帧，GIF 也计入「图片数量」和看图列表。
- **滚轮翻页 / 缩放**：看图窗口底部下拉选择「滚轮翻页」或「滚轮缩放」，选择会记住；缩放下滚轮以鼠标位置为中心缩放（1–6 倍），按住左键拖动画面，拖动不会误触发翻页。
- **定时自动翻页**：底部下拉框选间隔（不自动 / 2 / 3 / 5 / 10 秒），或按 **A** 键快速开关。自动翻到最后一页后等满一个间隔**自动关闭**。
- **看图窗口可以多开**：每点一次封面开一个新窗口，各看各的。窗口**不挂在主窗口下**，所以能各自出现在 Alt+Tab 和任务栏里，随时切回工具窗口。
- **点作品名称**在资源管理器里打开这个文件夹。
- **卡片右键菜单**：看图（左右键翻页） / 用 Windows 图片打开第一张 / 打开文件夹路径 / 给文件夹打标签… / 从工具中删除。
- **重扫自动清理**：再次扫描同一个目录时，磁盘上已经不存在、之前索引过的文件夹会被**真正删除**（标签关联一起清），状态栏会报告清理了几条。
  删除前会再确认一次路径确实不在磁盘上——外接盘临时没挂上不会误删。

**排序**（顶部下拉切换，选择会记住）
- **结尾 {页数,位置}**（默认）：优先按 `work-id.json` 的 `FavoritePage/FavoritePosition` **升序**——页码小的在前，同一页里序号小的在前；没有识别文件时回退到目录名末尾的 `{收藏夹页码,页内序号}`。
  目录名命名规则来自 AHRI8Backup：`标题{作者}{收藏夹页码,页内序号}`，例如 `a{b}{1,3}` 表示第 1 页第 3 个；多作者时是多个 `{作者}` 段，只认末尾那一组。
- **结尾 {页数,位置} 倒序**：同上但反过来——页码大的在前，同一页里序号大的在前。例如 `xxx{a}{2}` 排在 `xxx{a}{1}` 前面。
- 两种按数字排的模式下，没有识别文件且目录名也解析不出这组数字的（例如根目录自己）都排在最后，它们之间按名称排序。
- 末尾只写一个数字也认：`xxx{a}{2}` 按页码 2、位置 0 处理（仅在没有识别文件时使用）。
- **首字母 A→Z / Z→A**：按**标题**排序，标题优先取 `work-id.json` 的 `Title`，没有识别文件时取第一个 `{` 之前的内容。不分大小写。
- **识别文件 GlobalIndex**：按 `work-id.json` 里的 `GlobalIndex` 升序，没有识别文件的排最后。

**标签**
- **标签分类**：分类有独立的 `Categories` 表，可以**先单独建分类**、暂时不挂标签；标签用下拉框选择分类，新分类在标签管理里单独新增。筛选栏、打标签窗口、文件夹标签窗口都按分类分组，未分类的排最后。
- **左侧标签筛选两列**：分类标题下方按两列排列，左侧栏加宽到 300，标签多时少滚很多。
- **标签管理统一保存**：改名、选分类、删除、新建都先留在窗口里，点右下角「保存」一次写入；有未保存修改时关窗会确认。
- **给文件夹打标签**：多选文件夹，标签框三态显示（全选／半选／未选），一次批量添加或移除；每个文件夹行下方直接列出它已有的标签。
- **打标签窗口横向排列**：标签按分类分块、组内横向排列；新建标签时用下拉框选已有分类，新分类先在「标签管理」里新增。
- **打标签窗口独立于主窗口**：不设 Owner、不用 ShowDialog，主窗口和看图窗口在打标签时仍可操作；窗口有任务栏入口，可浮在其他窗口上。关闭后保持当前页和滚动位置，不回到顶部。
- 多标签 AND / OR 搜索；点卡片上的标签芯片即可按该标签筛选。父文件夹的标签会匹配它下面的子文件夹。

**其它**
- **导出清单**：把当前筛选出的文件夹导成文本清单——序号 / 文件夹名称 / 标签 / 完整路径，制表符分隔（可直接拖进 Excel 分列）。表头会写明导出时间、排序方式、关键字和标签筛选条件。
- **从工具中删除（不删磁盘目录）**：勾选卡片后批量移除，只删索引和标签关联。路径会记进隐藏列表，**重新扫描也不会再收进来**；移除文件夹会连同它下面的子目录一起移除。误删可用「恢复已隐藏」清空隐藏列表（需重扫恢复索引）。
- **删除文件夹及索引**：勾选一个或多个文件夹后点「删除文件夹…」，把磁盘上的文件夹**移到回收站**，同时删除本工具的索引和标签关联；部分失败会逐个报告，失败项保留索引。
- **深色滚动条**：`ScrollBar` 提供垂直/水平两套完整模板，颜色全部走 `DynamicResource`，深色/浅色主题切换时滚动条同步变色。
- **浅色 / 深色主题**：右上角按钮切换，选择会记住。
- **应用图标**：`Assets\app.ico`（附件里的文件夹 + 小狗照片 + `IMG_01` 标签，透明背景、多尺寸），
  资源管理器、任务栏、快捷方式和窗口标题栏都用这一张。
- **库另存为 / 读取库**：把标签、文件夹列表、标签关联、根目录和隐藏路径另存为 JSON（`.laslib.json`），
  换机器或重装后读取回来即可恢复，不用重新扫描/打标签；读取是合并，不会清空当前库。文档不包含图片。
- **索引和标签不放在 exe 目录**：始终保存在用户数据目录；删除、替换或重新下载 exe 都不影响。

## v0.17.2 变更

- **修正已有平移量时缩小的锚点公式**：之前用 `offset += local × (旧缩放 − 新缩放)`，只在 offset 为 0 时成立；
  放大后（offset 非 0）在屏幕左右侧再缩小，会被错误地算成一次大平移。现在用
  `anchor = (local − offset) / 旧缩放`、`新 offset = local − anchor × 新缩放`，缩小也真正围绕鼠标位置。
- 自检新增：构造已有 offset 的缩小场景，验证锚点屏幕位置不漂移。

## v0.17.1 变更

- **修正滚轮缩放的锚点**：改用 `Viewport` 坐标和 `Picture` 的布局原点计算，不再用 `e.GetPosition(Picture)`。
  后者会被 `RenderTransform` 影响，连续放大/缩小时锚点会漂移；现在放大和缩小都严格以鼠标位置为中心。
- 发布输出按你的要求只保留：**自包含单文件 exe** 和 **完整源码 zip**，不再提供框架依赖单文件/文件夹版。

## v0.4.2 变更：数据目录不可写时不再崩溃

v0.4.1 已经会把启动异常打印出来，于是暴露出真正的原因：

```
SqliteException: SQLite Error 8: 'attempt to write a readonly database'
   at Database.MigrateKindSchema(...)
```

**这不是代码缺陷，是运行环境把 `%LOCALAPPDATA%` 变成了只读。** 当进程被放进受限令牌里运行时（例如某些沙箱），
ACL 上只有 `CodexSandboxUsers` 组的「读取和执行」，用户自己的完全控制项不生效，于是 SQLite 连 WAL 的
`-shm` 文件都建不出来，直接报只读。表现就是「双击没反应」或「弹个错就退出」。

处理方式：

- **新增数据目录回退**：`Database` 启动时真正试探写入权限，`%LOCALAPPDATA%\LocalAssetSearch` 不可写就依次退到
  `exe 同目录\LocalAssetSearch-data`、最后 `%TEMP%\LocalAssetSearch`，程序照常可用。
- **回退时明确告知**：写日志并弹一次警告，说明当前用的是哪个目录、为什么会这样、以及建议改用正常方式启动。
- 实际使用的数据目录会记进日志，排查时一眼可见。

> 注意：回退目录里的库是**空库**。正常双击运行时数据仍在 `%LOCALAPPDATA%\LocalAssetSearch`。

## v0.4.1 变更：修复「双击没反应」

v0.4.0 的 exe 被 Defender 拦截，且即使放行也看不到窗口。两个问题的根因都是同一类：**失败时完全没有反馈**。

- **启动异常不再静默**：`App.xaml.cs` 不再依赖 `App.xaml` 的 `StartupUri`，改为在 `OnStartup` 里手动建窗口并 `try/catch`，
  同时挂上 `DispatcherUnhandledException` 与 `AppDomain.UnhandledException`。
- **新增启动日志** `Services/StartupLog.cs`：记录版本、exe 路径、数据目录和任何异常堆栈。优先写 exe 同目录，不可写则退回 `%TEMP%`。
- **失败时弹窗说明原因**，数据库写入失败还会给出具体排查步骤，并可一键打开日志所在文件夹。
- **新增 `app.manifest`**：`asInvoker`（不提权）+ 显式声明支持 Windows 10/11，避免系统套用兼容性垫片。
- **发布配置去掉杀软高误报项**：不再使用 `EnableCompressionInSingleFile`。

## v0.4.0 变更：移除 PDF 支持

扫描时不再收录 `.pdf`，索引里只有 `folder` 和 `image`；数据库 `Assets.Kind` 的 CHECK 约束由 `('folder','image','pdf')` 收紧为 `('folder','image')`。

> ⚠️ 升级会清掉旧的 PDF 记录。启动时若发现旧 schema（含 `pdf` 或更早的 `video`），会自动重建 `Assets` 表，
> 只保留 folder 和 image，并删除被丢弃记录上的标签关联。这一步不可逆，但不会碰你的原始文件。
> 不想丢的话，先备份 `%LOCALAPPDATA%\LocalAssetSearch\assets.db`。

## 依赖与下载量说明

**仍然需要 NuGet 依赖，无法做到完全零下载**，因为 .NET/WPF 本身不提供 SQLite 数据库驱动。

本项目不使用 PDFium、PDFtoImage 或独立 SQLite 原生二进制包，只用：

- `Microsoft.Data.Sqlite.Core` 8.0.11
- `SQLitePCLRaw.provider.winsqlite3` 2.1.6
- 上述包的传递依赖 `SQLitePCLRaw.core`（NuGet 自动解析）

SQLite 通过 Windows 自带的 `winsqlite3.dll` 运行。首次还原仍需从 NuGet 下载这些托管包；还原成功后通常会缓存在本机。

| **单文件 · 框架依赖**（`2-single-file-fx-dep`） | 约 731 KB | 需要 8.0.x | 不解包、不压缩，误报率最低 |
| **普通文件夹**（`3-folder-fx-dep`） | 约 600 KB | 需要 8.0.x | 无 bundle、无自解包，最普通的 .NET 桌面程序 |

### 单文件版到底需要什么

- **单文件 · 框架依赖**：Windows 10 1809+ / Windows 11，外加 **.NET 8 桌面运行时**（`Microsoft.WindowsDesktop.App` 8.0.x）。
- **单文件 · 自包含**：Windows 10 1809+ / Windows 11，**不需要安装 .NET**；需要 `%TEMP%` 可写（首次自解包）。
- 两者都不需要：.NET Framework、VC++ Redistributable、WebView2、DirectX 额外组件。
- SQLite 用的是 **Windows 自带的 `winsqlite3.dll`**（Windows 10 1809+ 内置，本机为 3.43.2），不需要单独安装。
  没有换成自带 `e_sqlite3.dll` 的 bundle：系统组件已经足够，少一个自解包原生库也能少一点 Defender 误报面。

### 图标文件

- 源文件：`Assets\app.ico`（16–256 多尺寸）与 `Assets\app-32.png`（窗口标题栏用）。
- 源码包 `LocalAssetSearch-v0.18.0-src.zip` 内包含这两个文件。
- `release\` 根目录也保留一份，方便查看或替换；exe 已内嵌图标，**替换 exe 旁边的 ico 不会改变 exe 本身**。

> 如果 `dotnet publish` 报 `MSB4018 ... Access to the path ...\LocalAssetSearch.exe is denied`，
> 说明**上一次发布出来的 exe 正被杀软或索引占用**，MSBuild 覆盖不了它，于是**保留了旧文件而发布实际失败**。
> 这种失败不看输出很容易漏掉（产物还在，只是旧的）。处理办法：确认没有进程在跑那个 exe、稍等几秒重试，
> 或输出到新的目录名。**发布后建议核对产物版本**：
> `(Get-Item .\LocalAssetSearch.exe).VersionInfo.ProductVersion`。

### 方案 A：框架依赖单文件（小体积，需 .NET 8）

```powershell
dotnet publish -c Release -r win-x64 --self-contained false `
  -p:PublishSingleFile=true
```

产物单个 exe，约 **0.7 MB**。需要目标机器已安装 **.NET 8 桌面运行时**。
**这条路径不会自解包、不做压缩**，既没有 TEMP 写权限依赖，也最不容易被杀软拦。

### 方案 B（推荐，免安装运行时）：自包含单文件

```powershell
dotnet publish -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true
```

产物单个 exe，约 **162 MB**，首次运行会把原生库解包到 `%TEMP%\.net\`。**TEMP 必须可写**，否则会在解包阶段直接失败。

- 不要加 `PublishTrimmed`，WPF 不支持裁剪。
- **不要加 `EnableCompressionInSingleFile=true`**：压缩后的自解包 exe 是 Windows Defender 机器学习启发式（常见报法 `Trojan:Win32/Wacatac.B!ml`）的高频误报目标。

### 方案 C：普通文件夹版（最不容易被拦）

```powershell
dotnet publish -c Release -r win-x64 --self-contained false `
  -p:PublishSingleFile=false
```

产物是普通的一堆文件（`LocalAssetSearch.exe` + 几个 DLL，合计约 480 KB），
**没有任何 bundle、压缩或自解包**，形态就是最普通的 .NET 桌面程序。需要 .NET 8 桌面运行时。

### 关于被 Defender / SmartScreen 拦截

本程序没有代码签名证书，而「体积较大 + 自解包 + 压缩」的 .NET 单文件 exe 与加壳恶意软件的形态高度相似，因此被误报很常见。应对方式：

1. 目标机器已装 .NET 8 时，优先用**方案 A**（约 0.7 MB、无解包、无压缩），误报率最低；
   未装运行时就用**方案 B**，但体积大、首次会自解包，误报和 TEMP 依赖都更高。
2. 若 exe 是从压缩包或网络复制来的，右键 → 属性 → 勾选「解除锁定」。
3. 仍然被拦就加排除项：Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项 → 添加文件/文件夹。
4. 想要彻底避免：给 exe 做代码签名（需要付费证书）。

另注：刚构建出来的 exe 第一次启动可能报一次「拒绝访问」，等一两秒重试即可——实时防护正在扫描新文件。

## 启动失败怎么排查

程序是 `WinExe`，**没有控制台窗口**，所以启动阶段的异常不会自己显示出来。因此：

- 启动过程会写日志：优先写在 **exe 同目录** 的 `LocalAssetSearch.log`，该目录不可写时退回 `%TEMP%\LocalAssetSearch.log`。
- 启动失败会弹窗说明原因，并提供「打开日志所在文件夹」。
- 若连弹窗都没出现，说明进程在托管代码运行前就死了 —— 基本是杀软拦截或（方案 B 的）自解包失败。
- 想确认各个窗口是否都能加载，可以运行 `LocalAssetSearch.exe --selftest`：它只构造窗口、不显示，把结果写进日志后立刻退出（退出码 = 失败数）。

## 数据位置

- SQLite 数据库：`%LOCALAPPDATA%\LocalAssetSearch\assets.db`（默认；**不会**放在 exe 目录）
- 缩略图缓存：`%LOCALAPPDATA%\LocalAssetSearch\Thumbnails\`
- 主题设置：`%LOCALAPPDATA%\LocalAssetSearch\settings.ini`
- 启动日志：exe 同目录的 `LocalAssetSearch.log`（或 `%TEMP%` 下同名文件）

默认目录不可写时，按 `%APPDATA%` → `%USERPROFILE%` → `%TEMP%` 顺序回退（见 v0.12.0）；
只有退到 `%TEMP%` 时才存在被系统清理的风险，启动时会弹窗说明。
